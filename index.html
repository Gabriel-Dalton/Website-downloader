Website Downloader

Mirror a website to a folder you can browse offline, assets included.

What this is

A small Node app you run on your own machine. Give it an address, it mirrors the site with wget, and hands back a zip you can open without a network connection.

There is no hosted version. This page is documentation, not the tool. It runs locally because it writes to disk and can pull down a gigabyte from a single media-heavy site.

Requirements

  • Node.js 16 or newer
  • wget on your PATH — nothing downloads without it
PlatformInstall wget
Debian / Ubuntuapt install wget
macOSbrew install wget

Running it

1

Clone and install.

git clone https://github.com/Gabriel-Dalton/Website-downloader.git
cd Website-downloader
npm install
2

Start the server.

npm start
3

Open http://localhost:3000, enter an address, and press download. Progress streams to the page as it runs.

What you get

A zip containing one folder per hostname — the site itself, plus any CDN it loads stylesheets, scripts, images or fonts from. Open START-HERE.html at the root to land on the front page.

Settings

VariableDefaultWhat it does
PORT3000Port the server listens on
DOWNLOAD_QUOTA2gSize ceiling, so a runaway crawl cannot fill the disk
DOWNLOAD_TIMEOUT_MS1800000How long one download may run before it is stopped

Hitting the size ceiling is reported on the page rather than passed off as a finished download. The archive is real, just short of the whole site.

What it will not do

A mirror is not a running website. Worth knowing where the edges are before relying on one.

  • Images a site loads through JavaScript after the page renders are not in the markup, so they are not captured.
  • Anything produced at runtime by calls to a live API — search, carts, comment threads — will not work offline.
  • Pages nothing links to are never found. If a page exists only in sitemap.xml, no crawler that follows links will reach it.

About this fork

A fork of AhmadIbrahiim/Website-downloader. It fixes downloads that reported success while producing an empty archive, and adds capture of assets from the CDNs most modern sites serve them from. The fixes for the original problem have been offered back upstream.
